# offiky 설계

작성일: 2026-09-15
대상 플랫폼: macOS 26.0 이상, App Sandbox 활성화

## 1. 목적

같은 사내 네트워크를 사용하는 맥 사용자들이 각자의 데스크톱 위에 16×16 픽셀 캐릭터로
존재를 표현하고, 전역 단축키로 한 줄 메시지를 주고받는 상주 앱이다.

핵심 가치는 두 가지다.

- 동료가 지금 자리에 있다는 감각을 작업 화면을 벗어나지 않고 얻는다.
- 말을 걸기 위해 다른 앱으로 전환하지 않는다.

## 2. 확정된 범위

| 항목 | 결정 |
|---|---|
| 좌표 공유 | 화면별 정규화 좌표를 공유한다. 해상도와 모니터 개수가 달라도 같은 비율 위치에 표시된다. |
| 채팅 | 말풍선 표시 + 메모리에 최근 50개 기록. 영속 저장은 하지 않는다. |
| 캐릭터 움직임 | 거점 주변 자동 산책. 드래그로 거점을 이동시킨다. |
| 참가 제한 | 없다. 같은 네트워크에서 앱을 실행하면 자동으로 참가한다. 전송은 평문이다. |
| 규모 | 동시 접속 50명 이상을 상정한다. |
| 전송 구조 | 서버 없이 Bonjour 로 발견하고 자동 선출된 호스트가 중계한다. |
| 표시 인원 | 접속자 전원을 표시한다. |
| 캐릭터 | 16×16 픽셀, 32×32 포인트로 표시한다. 사용자가 직접 편집할 수 있다. |

## 3. 앱 구조

`LSUIElement = true` 로 Dock 아이콘을 제거하고 `MenuBarExtra` 로 메뉴바에만 상주한다.

Xcode 템플릿이 생성한 `Item.swift`, `ContentView.swift`, SwiftData 관련 코드는 사용처가
없으므로 삭제한다.

메뉴바 메뉴 구성:

- 접속자 목록 (이름)
- 최근 메시지 50개
- 내 캐릭터 편집…
- 캐릭터 숨기기 (토글)
- 단축키 설정…
- 내 이름 변경…
- 종료

### 3.1 오버레이 윈도우

캐릭터 하나에 윈도우 하나를 배정하면 50명 규모에서 WindowServer 부담이 커진다.
**디스플레이마다 오버레이 윈도우 1개**를 배치하고 그 안의 SpriteKit 씬 하나가 해당 화면의
캐릭터 전부를 렌더링한다. 윈도우 개수는 모니터 개수와 같다.

윈도우 설정:

- `styleMask: .borderless`
- `isOpaque = false`, `backgroundColor = .clear`, `hasShadow = false`
- `level = .floating`
- `collectionBehavior = [.canJoinAllSpaces, .stationary, .fullScreenAuxiliary]`
- `frame = screen.visibleFrame` — 메뉴바와 Dock 이 차지한 영역을 제외한다

씬 설정:

- `preferredFramesPerSecond = 12` — 픽셀 스프라이트의 질감에 맞고 전체 화면 오버레이를
  60fps 로 렌더링할 때의 GPU·배터리 소모를 피한다
- `SKTexture.filteringMode = .nearest` — 2배 확대해도 픽셀 경계가 선명하게 유지된다

**클릭 통과**는 투명 픽셀 영역의 마우스 이벤트가 아래 앱으로 전달되는 동작에 의존한다.
내 캐릭터가 차지한 32×32 영역만 이벤트를 수신하고 동료 캐릭터는
`isUserInteractionEnabled = false` 로 지정한다. 이 가정의 검증과 대비책은 11절에 기록한다.

`NSApplication.didChangeScreenParametersNotification` 을 관찰한다. 모니터를 연결·해제하거나
배치·해상도를 변경하면 오버레이 윈도우 집합을 재구성하고 모든 캐릭터를 다시 배치한다.

`NSWorkspace.willSleepNotification` 에서 연결·리스너·브라우저를 정리하고,
`didWakeNotification` 에서 전부 재시작한다.

## 4. 캐릭터와 스프라이트

### 4.1 인코딩

스프라이트는 **16줄 × 16자 문자열**이다. 각 문자가 픽셀 하나를 나타낸다.

- `0`–`9`, `a`–`f` — 팔레트 인덱스
- `.` — 투명

**저장·전송에 사용하는 형식은 이 하나뿐이다.** 문자열 길이는 줄바꿈 포함 272바이트다.
`UserDefaults` 에 문자열 하나로 저장한다.

### 4.2 팔레트

PICO-8 16색을 사용한다.

| idx | hex | idx | hex |
|---|---|---|---|
| 0 | 000000 | 8 | FF004D |
| 1 | 1D2B53 | 9 | FFA300 |
| 2 | 7E2553 | a | FFEC27 |
| 3 | 008751 | b | 00E436 |
| 4 | AB5236 | c | 29ADFF |
| 5 | 5F574F | d | 83769C |
| 6 | C2C3C7 | e | FF77A8 |
| 7 | FFF1E8 | f | FFCCAA |

### 4.3 기본 캐릭터

소스에는 의미 기반 문자로 작성한다. **이 표현은 소스 내부에만 존재하며 외부로 전송되지
않는다.** 실행 시점에 팔레트를 적용해 4.1 의 인덱스 형식으로 변환한다.

```
................
.....######.....
....#HHHHHH#....
...#HHHHHHHH#...
...#HHHHHHHH#...
...#HSSSSSSH#...
...#HSESSESH#...
...#HSSSSSSH#...
....#SSSSSS#....
.....#SSSS#.....
......#SS#......
...#BBBBBBBB#...
..#SBBBBBBBBS#..
..#SBBBBBBBBS#..
...#BBBBBBBB#...
...#WW#..#WW#...
```

`.` 투명 / `#` 외곽선 / `H` 머리(가변) / `S` 피부 / `E` 눈 / `B` 옷(가변) / `W` 신발

고정 배정: `#`→`0`, `S`→`f`, `E`→`0`, `W`→`5`

가변 배정은 `id` 해시로 결정한다. 편집기를 한 번도 사용하지 않은 사용자에게만 적용된다.

- 머리 후보 8색: `0` `1` `2` `4` `5` `9` `d` `e`
- 옷 후보 8색: `2` `3` `8` `9` `b` `c` `d` `e`
- `h = hash(id)`, 머리 `= 머리후보[h % 8]`, 옷 `= 옷후보[(h / 8) % 8]`

조합 64가지로 50명을 구분한다.

### 4.4 애니메이션

**프레임은 1장만 사용한다.** 움직임은 전부 절차적으로 처리한다.

- 걷는 동안 1픽셀(2포인트) 상하 진동
- 멈춰 있을 때는 더 느린 상하 진동

스프라이트의 생김새를 전혀 몰라도 동작하므로 사용자가 어떤 그림을 그려도 자연스럽다.
좌우 뒤집기는 사용하지 않는다 — 기본 캐릭터와 대부분의 커스텀 캐릭터가 정면을 향하므로
뒤집어도 차이가 없다.

프레임 여러 장은 움직임이 심심하게 느껴질 때 추가한다.

### 4.5 이름 표시

이름은 기본적으로 숨긴다. **커서 반경 60포인트 안의 캐릭터**와 **말풍선을 표시 중인
캐릭터**만 이름을 표시한다. 씬 갱신마다 `NSEvent.mouseLocation` 을 조회하므로 추적 영역이나
접근성 권한이 필요 없다.

이름을 항상 표시하면 32포인트 캐릭터보다 이름표가 넓어져, 작게 표시하기로 한 이유가
사라진다.

`SKLabelNode`, 시스템 폰트 10pt, 캐릭터 하단에 배치한다.

### 4.6 말풍선

- 최대 너비 200포인트, 최대 3줄, 초과분은 말줄임표로 처리한다
- 5초간 표시한 뒤 사라진다
- 씬 경계를 벗어나지 않도록 위치를 제한한다

### 4.7 산책과 드래그

각 캐릭터는 **거점**을 가진다. 산책은 거점 반경 150포인트 안에서만 이루어진다.

- 수 초마다 반경 안의 임의 지점을 목표로 선택하고 약 20pt/s 로 이동한다
- 드래그하면 놓은 지점이 새 거점이 된다
- 동료 캐릭터의 움직임은 네트워크에서 수신한 좌표로 결정되며 로컬에서 산책을 계산하지 않는다

## 5. 좌표 모델과 다중 디스플레이

캐릭터 위치는 `(d: Int, x: Double, y: Double)` 로 표현한다.
`x`, `y` 는 해당 화면 `visibleFrame` 안에서의 0~1 비율이고, `d` 는 발신자의 화면 인덱스다.

수신 측 화면 선택:

```
screenIndex = (d + hash(id)) % NSScreen.screens.count
```

`hash(id)` 를 더하는 이유는 쏠림을 방지하기 위해서다. 대부분의 사용자는 모니터 1대라
`d = 0` 을 전송하므로, 단순히 `d % count` 를 사용하면 모니터 3대인 사용자의 화면에서
50명이 전부 0번 화면에 표시되고 확장 모니터가 비게 된다.

이 방식의 성질:

- 캐릭터가 어느 화면에도 속하지 않는 상태가 발생하지 않는다
- 모니터를 비대칭으로 배치했을 때 전체 데스크톱 경계 상자에 생기는 빈 영역 문제가 없다
- 한 세션 동안 같은 사람은 항상 같은 화면에 표시되므로 찾기 쉽다
- 화면 개수가 줄어들면 나머지 연산으로 접혀 남은 화면으로 자동 이동한다

## 6. 네트워크

### 6.1 발견

전원이 `_offiky._tcp` 서비스를 광고하면서 동시에 탐색한다. Network.framework 에서
Bonjour 광고는 `NWListener` 가 담당하므로 **모든 피어가 리스너를 연다.** 리스너를 열지 않은
피어는 발견되지 않아 선출 대상 집합에 포함되지 않는다.

방화벽 승인은 앱당 한 번이고, Developer ID 서명 앱은 기본 설정에서 자동 허용된다.

TXT 레코드: `id`, `name`, `pv`(프로토콜 버전)

`id` 는 **앱을 실행할 때마다 새로 생성하는 UUID** 다. 설치 고유 값이 아니다. 이 선택이
두 가지 문제를 동시에 해결한다.

- 선출 기준이 로컬 시계에 의존하지 않는다. 시각이 어긋난 맥 하나가 영구 호스트가 되는
  상황이 발생하지 않는다.
- 채팅 일련번호 `seq` 가 항상 새 `id` 와 함께 0부터 시작하므로, 재접속 후 메시지가
  "이미 본 번호"로 판정되어 전부 무시되는 문제가 발생하지 않는다.

이름과 스프라이트는 `UserDefaults` 에 보관하므로 재시작해도 유지된다.

### 6.2 호스트 선출

투표 프로토콜은 없다. 모든 피어가 보이는 피어 목록을 **`id` 문자열 오름차순**으로 정렬하고
맨 앞을 호스트로 계산한다. 같은 목록을 보면 같은 답이 나온다.

- 자신이 호스트면 들어오는 연결을 수락하고 중계를 시작한다
- 아니면 호스트에게 `NWConnection` 을 연결한다
- 피어 목록 변경 후 **300ms 디바운스**를 적용하고 재계산한다. 여러 명이 동시에 합류·종료할 때
  연쇄 재연결을 방지한다

**연결이 끊어진 피어는 Bonjour 목록에서 사라지기를 기다리지 않고 즉시 후보에서 제외하고
재계산한다.** 호스트가 비정상 종료하면 mDNS TTL 만료까지 수십 초가 걸리므로, 이 처리가
없으면 그 시간 동안 전원이 멈춘다. 제외 상태는 10초간 유지한 뒤 해제한다.

두 명이 동시에 자신을 호스트로 판단하는 구간이 잠깐 발생할 수 있다. 목록이 수렴하면
해소되고, 그 사이 잘못 연결된 클라이언트는 다음 재계산에서 이동한다.

`id` 가 실행마다 바뀌므로 호스트 역할은 자연히 분산된다.

### 6.3 프로토콜

줄바꿈으로 구분한 UTF-8 JSON 이다. `Codable` 로 처리하고 `nc` 로 직접 확인할 수 있다.

클라이언트 → 호스트:

```
{"t":"hello","pv":1,"id":"...","name":"Kyle","sprite":"...16줄..."}
{"t":"pos","d":1,"x":0.32,"y":0.71}
{"t":"say","seq":7,"msg":"점심 먹으러 갈 사람"}
{"t":"sprite","sprite":"...16줄..."}
```

호스트 → 클라이언트:

```
{"t":"join","id":"...","name":"Kyle","sprite":"...16줄..."}
{"t":"leave","id":"..."}
{"t":"snap","p":[{"id":"...","d":1,"x":0.3,"y":0.7}]}
{"t":"say","id":"...","seq":7,"msg":"점심 먹으러 갈 사람"}
{"t":"ack","seq":7}
{"t":"sprite","id":"...","sprite":"...16줄..."}
```

좌표를 `u`/`v` 가 아니라 `x`/`y` 로 표기하는 이유는 `v` 가 버전 필드와 충돌하기 때문이다.
프로토콜 버전은 `pv` 를 사용한다.

새로 접속한 클라이언트에게는 호스트가 **알고 있는 피어 수만큼 `join` 을 연속 전송한다.**
별도의 명부 메시지 형식을 두지 않는다.

### 6.4 위치 전파

- 클라이언트는 0.5초마다 자기 좌표를 전송한다. **드래그하는 동안에는 100ms 주기로 전송한다.**
- 호스트는 0.5초마다 전원의 좌표를 담은 스냅샷 하나를 각 클라이언트에게 전달한다.
  **호스트 자신의 좌표도 스냅샷에 포함된다.**
- 유실되어도 다음 스냅샷이 덮어쓰므로 재전송하지 않는다
- 수신 측은 스냅샷 사이 0.5초를 선형 보간해 캐릭터가 순간이동하지 않고 걸어가는 것처럼
  표시한다

50명 기준으로 스냅샷 1건은 약 3.5KB 이고 호스트 송신량은 약 350KB/s(2.8Mbps)다.
유선 LAN 에서는 문제가 없지만 Wi-Fi 에서는 무시할 수준이 아니다.

전원을 담은 스냅샷을 유지하는 이유는 유실과 순서 뒤바뀜에 저절로 복구되기 때문이다.
송신량이 실제로 문제가 되면, 직전 스냅샷 이후 좌표가 변한 피어만 포함하고 5초마다 전체를
전송해 재동기화하는 방식으로 전환한다. 캐릭터는 대부분 정지해 있으므로 평상시 송신량이
10분의 1 수준으로 줄어든다. 측정 전에는 적용하지 않는다.

### 6.5 채팅 전파

- 호스트가 즉시 전원에게 전달하고 발신자에게 `ack` 를 반환한다
- 클라이언트는 `ack` 를 받을 때까지 메시지를 대기열에 보관하고, **호스트가 교체되면 새
  호스트에게 재전송한다.** 중계자가 바뀌는 순간에 메시지가 조용히 사라지는 것이 이 구조에서
  가장 눈에 띄는 실패라서 여기만 재전송을 적용한다
- **호스트 자신이 보낸 메시지는 즉시 전파되므로 대기열과 `ack` 를 사용하지 않는다**

**중복 제거**는 피어별 마지막 `seq` 정수 하나로 처리한다. `seq <= 마지막값` 이면 무시한다.
최근 기록 50개로 판정하면 51번째 이후에 도착한 늦은 재전송을 검출하지 못한다.
피어당 8바이트로 완전하게 처리된다.

### 6.6 스프라이트 전파

스프라이트는 위치와 성격이 달라 다른 경로로 전달한다. 272바이트를 0.5초마다 50명분
재전송할 이유가 없다.

- 접속할 때 `hello` 에 포함해 전송한다. 호스트가 보관하고 전원에게 `join` 으로 전달한다
- 편집기에서 저장하면 `sprite` 메시지를 전송하고 호스트가 전원에게 전달한다
- 위치 스냅샷에는 `id` 와 좌표만 포함한다

### 6.7 입력 검증

수신한 데이터는 다른 사람의 맥에서 실행되는 코드가 생성한 것이므로 신뢰할 수 없는 입력으로
처리한다. **이것이 외부 데이터가 들어오는 유일한 통로다.**

| 대상 | 규칙 | 위반 시 |
|---|---|---|
| 메시지 1건 크기 | 16 KB 이하 | 연결 종료 |
| 스프라이트 | 정확히 16줄, 각 줄 16자, `0-9a-f.` 만 사용 | 기본 캐릭터로 대체 |
| 이름 | 1~20자, 제어 문자 제외 | 연결 종료 |
| 채팅 본문 | 1~200자, 제어 문자 제외 | 해당 메시지 무시 |
| 좌표 | `x`, `y` 가 0.0~1.0, `d` 가 0 이상 | 해당 항목 무시 |
| `pv` | 알고 있는 버전과 일치 | 연결 종료 |

### 6.8 샌드박스 설정

- entitlement: `com.apple.security.network.client`, `com.apple.security.network.server`
- `Info.plist`: `NSBonjourServices = ["_offiky._tcp"]`, `NSLocalNetworkUsageDescription`
- macOS 15 부터 로컬 네트워크 접근에 사용자 승인이 필요하다

## 7. 채팅 입력과 단축키

전역 단축키는 SwiftUI 에 API 가 없다. Carbon `RegisterEventHotKey` 를 직접 사용하면 약 50줄의
보일러플레이트가 생기고 사용자 재지정 UI 를 따로 만들어야 하므로, `KeyboardShortcuts`(SPM)
의존성 하나를 추가한다.

기본값은 `⌃⌥Space` 다. `⌥Space` 는 다른 런처와 충돌하는 경우가 많다.

단축키를 누르면 커서가 있는 화면 중앙에 작은 `NSPanel` 이 표시되고 포커스를 가져온다.

- Enter — 전송하고 패널을 숨긴다
- Esc — 취소한다
- 전송한 메시지는 내 캐릭터 머리 위에 5초간 말풍선으로 표시되고 동시에 전원에게 전달된다

최근 메시지 50개는 메모리 링버퍼에 보관하고 메뉴바에서 조회한다. 디스크에 저장하지 않으므로
앱을 종료하면 사라진다.

## 8. 캐릭터 편집기

메뉴바에서 "내 캐릭터 편집"을 선택하면 편집 창이 표시된다.

- 16×16 격자. 드래그하면 연속으로 칠해진다
- 하단에 16색 팔레트와 투명(지우개) 스와치
- `⌘Z` 되돌리기
- "기본 캐릭터로 초기화"
- 저장하면 `UserDefaults` 에 기록하고 `sprite` 메시지를 전송한다

색을 자유 선택 대신 고정 16색으로 제한하는 이유는 두 가지다. 픽셀 한 칸이 문자 하나로
유지되어 스프라이트가 272바이트에 담기고, 색이 제각각이라 그림이 탁해지는 것을 방지한다.

레이어, 프레임 여러 장, PNG 가져오기·내보내기는 넣지 않는다.

## 10. 검증

네트워크와 UI 없이 실행할 수 있도록 순수 함수로 분리해 기존 `offikyTests` 타깃에서 검증한다.

1. **호스트 선출** — 피어 목록을 입력하면 호스트 `id` 를 반환한다.
   `id` 정렬이 결정적인지, 연결이 끊어진 피어가 제외되는지, 목록이 비면 자신이 호스트가 되는지
   검증한다.
2. **좌표 환산** — `(d, x, y)` 와 화면 배열을 입력하면 화면 인덱스와 전역 좌표를 반환한다.
   모니터가 2대에서 1대로 줄어들 때 캐릭터가 화면 안에 남는지, 여러 피어가 화면에 분산되는지
   검증한다.
3. **중복 제거** — 호스트 교체 후 재전송된 메시지가 한 번만 표시되는지, 늦게 도착한 오래된
   `seq` 가 무시되는지 검증한다.
4. **스프라이트 인코딩** — 문자열로 변환한 뒤 되돌렸을 때 같은 그림인지, 줄 수·글자 수·허용
   문자를 벗어난 입력이 전부 거부되는지 검증한다.

나머지(윈도우 속성, SpriteKit 렌더링, 실제 Bonjour 발견, 다중 디스플레이 동작)는 맥 두 대
이상으로 직접 확인한다.

## 11. 알려진 한계와 위험

**투명 픽셀 클릭 통과는 검증되지 않은 가정이다.** 이 가정이 틀리면 전체 화면 오버레이가
모든 클릭을 가로채 맥을 사용할 수 없게 된다. 구현 1단계에서 가장 먼저 확인한다.
실패할 경우 오버레이를 `ignoresMouseEvents = true` 로 지정하고, 내 캐릭터용 작은 윈도우
하나만 별도로 배치한다. 동료 캐릭터는 어차피 클릭을 받지 않으므로 추가되는 윈도우는 1개다.

**전송이 평문이고 참가 제한이 없다.** 같은 대역대의 누구나 대화를 읽을 수 있다. 프로토콜에
`pv` 필드를 두었으므로, 나중에 TXT 레코드에 팀 키 해시를 추가하고 TLS-PSK 로 전환할 수 있다.

**부분 네트워크 장애 시 화면이 분리될 수 있다.** 특정 피어와 호스트 사이만 끊어지면 그
피어는 다른 호스트를 선택해 나머지와 분리된다. LAN 에서는 드물고 재연결되면 해소되므로
완전 해결 대신 알려진 한계로 둔다.

**mDNS 가 서브넷을 넘어가지 않으면 다른 층 사람이 보이지 않는다.** 네트워크 구성에 따른
제약이다.

**캐릭터가 항상 작업 창 위에 표시된다.** `.floating` 레벨이므로 발표나 집중 작업에 방해가
된다. 메뉴바의 "캐릭터 숨기기" 토글이 필수 탈출구다.
